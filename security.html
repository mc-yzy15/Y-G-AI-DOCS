API Key 安全

API Key 等同于账号资产。一旦泄露，可能被他人盗刷额度，请务必遵循以下最佳实践。

基本原则

绝不入库

不要把 API Key 写进代码仓库、配置文件或前端页面。使用环境变量或密钥管理服务。

最小权限

为不同用途创建独立令牌，并为令牌设置额度上限，限制异常消耗。

定期轮换

定期在控制台更换令牌，人员离职或项目移交时立即重置。

及时止损

发现泄露第一时间在控制台禁用 / 删除对应令牌，再排查泄露途径。

服务端代码示例

Python（推荐）
import os
from openai import OpenAI

# 通过环境变量注入，而非硬编码
client = OpenAI(
    api_key=os.environ["YINGGUANG_API_KEY"],
    base_url="https://ai.yzy15.dpdns.org/v1",
)

resp = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)

前端注意

不要把 API Key 放在浏览器端 JavaScript、小程序代码或 .env 中公开部署。正确做法是：前端请求你的后端，由后端安全调用模型 API。

泄露后处理清单

  1. 立即到控制台「令牌」页面禁用被泄露的令牌。
  2. 检查「日志」与「用量」是否存在异常请求。
  3. 删除原令牌并创建新令牌，更新所有使用方。
  4. 排查泄露源头：是否提交到公开仓库、是否贴到公共对话、是否存储在不安全位置。

其他安全建议

  • 使用独立的强密码登录官网，不要与其他平台复用。
  • 不向任何人索要或提供你的 Key（平台客服不会索要密码与 Key）。
  • 定期查看「日志」页面，关注异常调用时段与频率。
