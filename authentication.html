鉴权与 Base URL

所有请求都需要携带你的 API Key。不同协议下 Key 的传递方式略有差异，本文给出完整对照。

Base URL（API 地址）

主地址、备用地址与 CN2 专线提供相同的接口与数据。主地址不可用时，可将客户端 Base URL 切换为备用地址或 CN2 专线，实现高可用。

鉴权方式对照

协议鉴权头示例
OpenAI Chat / Responses Authorization Authorization: Bearer sk-...
Anthropic Messages x-api-key（或 Authorization） x-api-key: sk-...
Gemini x-goog-api-key 或 ?key= ?key=sk-...
三种协议都可以用同一个 API Key。若你的客户端只支持 Authorization: Bearer，Anthropic 兼容入口通常也接受该写法，具体以当前部署为准。

OpenAI 兼容鉴权

curl
curl https://ai.yzy15.dpdns.org/v1/chat/completions \
  -H "Authorization: Bearer sk-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"你好"}]}'

Anthropic 兼容鉴权

curl
curl https://ai.yzy15.dpdns.org/v1/messages \
  -H "x-api-key: sk-YOUR_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-20250514",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "你好"}]
  }'

Gemini 兼容鉴权

curl
curl "https://ai.yzy15.dpdns.org/v1beta/models/gemini-2.5-flash:generateContent?key=sk-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{"parts": [{"text": "你好"}]}]
  }'

常见鉴权错误

HTTP 状态码含义排查建议
401 UnauthorizedKey 缺失或无效确认 Key 未被复制遗漏、未被删除或过期
403 Forbidden无权限确认账号余额充足、该模型未对当前分组禁用
429 Too Many Requests触发频率限制降低请求频率，或提高分组并发上限
切勿将 API Key 明文写入公开代码仓库或前端页面，否则可能被盗用并造成资损。详见「API Key 安全」。
